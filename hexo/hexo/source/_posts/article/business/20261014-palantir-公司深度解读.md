## 一句话定位

**Palantir 不卖模型，它卖"把数据变成决策"的操作系统。**

如果大模型是燃料，Palantir 修的是管道和炼油厂。CEO Alex Karp 的原话更狠：纯 token 化的 AI 是给企业加的一种"财富税"——**如果 token 不能改变一个决策，它就没有价值。**

它做三件事：

| 平台 | 面向 | 一句话 |
|------|------|--------|
| **Gotham** | 政府 / 国防 / 情报 | 从太空到泥地的作战与情报决策 |
| **Foundry** | 商业企业 | 用 Ontology 驱动的数据操作系统 |
| **AIP** | 全客户 | 把 LLM 接到真实业务操作上，而不是停在聊天框 |
| **Apollo** | 底层 | 跨任意环境自主部署、监控、管理软件 |

官网 2026 年的口号是 **"Sovereign AI Systems for Every Decision"（为每一个决策而生的主权 AI 系统）**——"主权 AI"（Sovereign AI）是它现在最核心的销售叙事。

## 产品矩阵与业务地图

Palantir 的价值链**不是模型本身**，而是把"数据、权限、工作流"接成一套可执行、可审计的运营系统。

```
┌─────────────────────────────────────────────┐
│  AIP（生成式 AI 层）  ·  Foundry（数据运营层）   │  ← 300+ 微服务
│         ↑ 都跑在 Ontology（本体）之上 ↑          │
├─────────────────────────────────────────────┤
│  Apollo（无人值守的持续交付 / 部署层）            │
├─────────────────────────────────────────────┤
│  零信任安全底座 · 多云 / 断网 / 边缘环境           │
└─────────────────────────────────────────────┘
```

| 平台 | 客户类型 | 核心能力 | 代表客户 / 项目 |
|------|----------|----------|------------------|
| **Gotham** | 国防、情报、公共安全 | 多源数据 → 统一作战视图，权限内调查、资源配置、任务协同 | 美军、乌克兰、以色列国防部 |
| **Foundry** | 商业企业 | 把 ERP / 工厂 / 供应链 / 医疗 / 金融数据接入统一 Ontology | AT&T（660 个应用）、Heineken、Walgreens、Panasonic |
| **AIP** | 全客户 | LLM 在权限、数据、工作流内执行，而非纯聊天 | Wendy's、Lowe's、AARP、CAZ Investments |
| **Apollo** | 底层 | 每周编排**数万次发布**，任意环境自主部署 | 所有部署环境 |
| **Maven Smart System** | 美军 | 整合卫星 / 无人机 / 情报报告，快速目标选择 | 五角大楼正式记录项目 |

**政府王牌**：Maven 平台投资规模已从 2024 年的 4.8 亿美元膨胀到约 **130 亿美元**，华尔街预计该项目年经常性收入（ARR）可达约 10 亿美元。它已被定位为"美军最大的 AI 供应商"。

**商业渗透**：AT&T 在 Foundry 上跑了 **660 个应用**；Walgreens 从"半年 10 家店试点"扩到"八个月 4000 家店"。这些案例的共同点是——**从试点到生产的落地速度，是它真正的卖点。**

## 技术内核：Ontology 为什么是护城河

> 这是全文最关键的技术部分。看懂 Ontology，就看懂了 Palantir 为什么"抄不走"。

### 1. 它不是哲学概念，是"企业操作系统的心脏"

Ontology（本体）**不是数据层，而是决策层**。它建模的不是"数据"，而是**企业的决策**。官方定义：Ontology 通过**四重整合**来建模决策——

| 维度 | 含义 | 类比 |
|------|------|------|
| **Data（数据）** | 从 ERP、CRM、传感器、文档等任意来源汇入 | 名词（nouns） |
| **Logic（逻辑）** | 业务规则、ML 模型、LLM 函数、多步编排 | 推理 |
| **Action（行动）** | 从简单事务到多步写回的生产系统更新 | 动词（verbs） |
| **Security（安全）** | 细粒度 RBAC，人 / Agent 执行前都要过权限校验 | 护栏 |

"名词"必须配上"动词"才能建模决策——**语义（semantics）必须与动力学（kinetics）配对**。这是 Ontology 与普通"语义层"的根本区别。

### 2. 分层架构

```
┌──────────────────────────────┐
│ 应用层（Apps / AIP Agents）    │  ← 通过 OSDK / API 交互
├──────────────────────────────┤
│ Ontology Layer                │  ← 核心：Object Store + 安全策略引擎
├──────────────────────────────┤
│ 数据层（Datasets）             │  ← 原始数据湖 / 数仓
└──────────────────────────────┘
```

- **Object Store**：核心数据库，存对象实例及其关系图（Graph），V2 支持**数十亿对象低延迟查询**
- **Funnel**：把底层数据集变更（CDC）实时索引进 Object Store
- **OSDK**：强类型 TS / Java SDK，让应用直接与 Ontology 交互，而不是直连数据库

### 3. 它是"给 AI 的业务说明书"——解决大模型的企业失明

这是 Palantir 最深的护城河。**通用大模型不知道企业内部术语、数据位置和权限**，Ontology 充当了 Grounding（背景知识）层：

- 当用户问 AIP"帮我查订单 123 的状态"，AIP **不会直接问 LLM**，而是先查 Ontology，把"订单 123"解析为具体 Object，再把相关 Property 和权限上下文组装成 Prompt 喂给 LLM。
- 结果：**LLM 只在给定的、安全的 Ontology 上下文里推理，极大减少幻觉**。
- **Agent 的工具（Tools），本质就是 Ontology 里定义的 Action**。

### 4. 为什么"抄不走"

业界有个精准判断：

> **抄 Bootcamp 流程的，没有 Ontology 沉淀；抄 Ontology 的，没有 FDE 团队；抄 FDE 的，没有 Bootcamp 销售模式。**
>
> 8 家厂商抄得走 Palantir 的 Ontology 概念，**抄不走它的会计科目**。

Ontology 是"技术共识"，可以被快速复制；**Bootcamp 商业模式是"商业创新"，不能**。这就是它护城河的真实结构：**技术 + 组织 + 商业模式的组合拳，缺一不可。**

## 商业模式：FDE + Bootcamp 如何把"最难卖"变成"最赚钱"

### 曾经的困境：性价比极低的重人力模式

Palantir 曾是企业软件里**最难卖**的公司之一。因为它卖的不是软件，而是一套需要深度定制的方法论：

- 传统软件销售靠"演示 + 承诺"：你买了它就能做这些。
- Palantir 的卖点是："**让我们用你的真实数据和真实问题来证明**"。
- 意味着每一次销售都要投入大量**前线工程师（FDE）**的时间，人肉成本极高。

**财务上的体现**：2020 年 GAAP 净利率低至 **-107%**（全年亏损 11.7 亿美元 > 营收 10.9 亿）；2021 年 -34%，2022 年 -20%，连续三年深度亏损。主因是巨额股权激励（SBC）：2020 年全年 SBC 约 12.7 亿美元，**约为当年营收的 119%**。

### 转折点：AIP Bootcamp + 平台复用

两件事改写了单位经济学：

1. **AIP Bootcamp**：客户在几小时到几天内，用手上的真实数据跑出结果。**大幅降低获客成本**，把"推销"变成"现场交付成果"。
2. **平台复用**：从"依赖具体的人"转向"依赖已沉淀的资产、方法论、系统"。**AI 进一步放大了平台复用能力**。

**结果（费用率直线下降）**：

| 费用率 | 2022 Q2 | 2026 Q2 | 变化 |
|--------|---------|---------|------|
| 销售费用率 | 36% | 18% | -18pct |
| 研发费用率 | 19% | 10% | -9pct |
| 管理费用率 | 33% | 10% | -23pct |
| **合计** | **88%** | **38%** | **-49pct** |

### 收入模型

| 收入形式 | 说明 |
|----------|------|
| 软件订阅 | 核心，经常性收入 |
| 云 / 托管服务 | 部署与运维 |
| 专业服务 | FDE 现场交付，占比逐年下降 |
| 合同形态 | 按合约履约确认收入；**ARR / TCV 不是当季收入** |

**关键认知**：合同金额、示范项目、单次 AI 使用量，都**不等于**经常性收入。真正要验证的是链路——**试点 → 生产部署 → 客户扩张 → 毛利与留存 → FCF → 每股价值**，能不能连续成立。

## 竞争格局：谁会真正威胁它

**Palantir 没有一个完全同构的上市对手**——它同时进入数据平台、AI 应用、企业软件、国防任务软件、政府服务预算。必须**按工作负载分组**来比较。

| 竞争组 | 代表公司 | 对方优势 | Palantir 的相对位置 | 风险 |
|--------|----------|----------|----------------------|------|
| **数据云 / Lakehouse** | Snowflake、Databricks | 数据基础、开放格式、开发者生态 | Ontology、业务动作、复杂部署更深 | 对方持续向 AI 应用和智能体上移 |
| **云平台 / 企业套件** | Microsoft Fabric / Azure、AWS、Google Cloud | 生态捆绑、合同、企业分发 | 跨云、断网隔离、任务深度、现场部署 | 套件价格与采购便利压缩独立平台预算 |
| **国防 C2 / 自治系统** | Anduril Lattice | 传感器、边缘硬件、自治系统闭环 | 数据整合范围更广，覆盖政府+商业 | C2 / 态势 / 决策软件边界直接重叠 |
| **政府服务 / 系统集成** | Booz Allen、Accenture、Deloitte | 客户关系、采购、人力规模 | 软件毛利与复用性更高 | 集成商可能影响架构选择 |
| **行业 AI 应用** | C3.ai | 行业应用直接落位 | 强调匹配客户数据的灵活性 | 在 AI 预算上被直接比较 |
| **工作流自动化** | ServiceNow | IT / 员工 / 客服流程自动化 | 从数据推导决策并驱动现场运营 | 争夺企业流程 AI 预算 |
| **客户自研 / 开源** | 内部平台团队、开源栈 | 控制度高、避免锁定 | 交付速度、统一治理、复杂部署 | 高能力客户可用模块化组件替代部分功能 |

### 关键判断

> **不是"Palantir 赢，其它全输"，而是市场在分层：**
>
> - **Palantir** 吃"高价值、复杂业务、需要 FDE 沉淀"的**高端市场**
> - **Databricks / Snowflake** 吃"标准化数据治理、不需要 FDE"的**中端市场**
> - **SAP / Salesforce / ServiceNow** 吃"业务系统原生、从业务出发"的**细分市场**
>
> 三层市场、三种打法，**每层一个赢家**。Palantir 暂时是高端赢家——但这是 2026 年的判断，不是终局。

**主权 AI 新变量**：Palantir 与 Nebius 的合作，把"数据、权重、微调都留在客户自己边界内"变成卖点，正面对冲"直接用我们的前沿模型 + 我们的云"这一默认叙事。这不是"PLTR 通吃"，而是"软件与算力围绕**主权**重新捆绑"。

## 对 AI 从业者 / 内容创作者的三点启示

1. **"模型是商品，rails 才是生意"**——对做 AI 应用的人来说，Palantir 的启示是：**别只做套壳聊天，要把 AI 接到具体业务动作和权限上**，这才是能收钱的 AI。
2. **Ontology 的思路可以"降维"借鉴**——中小团队不必造 Palantir，但可以学它的核心：**先定义业务对象和动作（名词+动词），再把 LLM 挂上去**，幻觉会显著下降。
3. **Bootcamp 是最好的内容素材**——"客户用真实数据，几小时跑出结果"的叙事，天然适合写成教程 / 案例，也正好契合 Python 办公自动化读者"**要能落地**"的偏好。
