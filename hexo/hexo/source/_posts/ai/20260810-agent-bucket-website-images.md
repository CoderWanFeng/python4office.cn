# 我用腾讯云 Agent Bucket 给网站图片找了个 AI 管家，再也不怕图床跑路

> **阅读时间：** 8 分钟
> **适用人群：** 有个人网站/博客、被外链图床坑过的开发者
> **涉及工具：** 腾讯云 Agent Bucket、Python、S3 SDK

---

上周打开自己网站，发现一篇文章的封面图裂了。

评论区有人问："是不是网站挂了？" 文章本身没坏，坏的是配图——那张图挂在第三方图床上，图床把资源清了，链接直接 404。

这种事故不算新鲜。网站跑了几年，几百篇文章，图片基本都放在外部图床上。免费、速度快，代价是图片的生死不归自己管。

当时就决定换方案：图片必须存自己手里，还要带管理能力——能检索、能去重、能分享。找了一圈，最后落在腾讯云的 Agent Bucket 上。

这篇文章记录完整的迁移过程，包括用的代码和踩的坑。结论先行：现在网站图片全部入库，找图靠描述，重复图自动去重，链接自己可控。

## 一、先说说网站图片有多乱

动手之前做了个盘点，结果比预想严重：

本地图片只有 34 张，散落在各个工作目录里。正文里几百篇文章的配图，几乎全部来自 Pexels、Unsplash 这类外部图床，没有一张是自己可控的。

外链图床的问题集中在这三条：

**第一，随时可能失效。** 图床改政策、CDN 波动、资源被清理，任何一环出问题，文章里的图就裂。读者体验受损，SEO 也跟着掉。

**第二，检索靠记忆。** 图散在各处，想找"某篇封面那种蓝色底的大图"，只能一个个文件夹翻。几千张图下来，人脑根本记不住文件名。

**第三，重复没人知道。** 同一张图被多篇文章引用，反复上传，占双份空间。没人统计过，也没法统计。

## 二、改造第一步：把图片统一收进 Agent Bucket

方案的核心是给每类内容一个独立的"空间"。Agent Bucket 在对象存储里加了 Space 这一层——一个桶下面可以建多个空间，每个空间独立凭证、独立配额，文件能力（去重、检索、分享）全部内置在存储层。

开通之后，先建桶，再建一个叫 `python4office-images` 的 Space，专门放网站图片。

Agent Bucket 兼容标准 S3 接口，Python 上传代码量很小：

```python
import boto3
from pathlib import Path

s3 = boto3.client(
    "s3",
    endpoint_url="https://cos.ap-shanghai.myqcloud.com",
    aws_access_key_id="你的 SecretId",
    aws_secret_access_key="你的 SecretKey",
)

bucket = "python4office-images"
space = "website"

for img in Path("./images").glob("*.*"):
    key = f"{space}/{img.name}"
    s3.upload_file(str(img), bucket, key)
    print(f"uploaded: {key}")
```

跑完一遍，把散落的图片全部收进 Space。

上传过程中有个意外收获：网站里不少文章引用的是同一张封面图，第二次上传相同文件时直接"秒传"。后台用 SHA-256 算文件指纹，重复内容不再占空间。对网站这种"大量重复引用"的场景，这个功能最省事——不用自己写去重逻辑。

## 三、改造第二步：让 AI 接管图片

传统对象存储只管存，查图只能靠文件名。Agent Bucket 把检索能力下沉到了存储层，可以直接描述图片内容去找。

比如想找一张"蓝色科技感的封面图"，不需要记得文件名，描述一下，系统按内容把命中的图列出来。这个能力对几千张图的管理很关键——人记不住文件名，但记得住"那张蓝色的图"。

[待插入截图：多模态检索演示——描述性搜索命中结果]

分类也交给了 AI。写了一个 Agent 任务：图片入库时按用途自动打标签——封面图、教程截图、公众号头图，分到不同目录。以前这种整理靠手动，现在存进去的时候顺手就分好了。

[待插入截图：AI 自动分类结果]

这里多说一句：把"检索、去重、分类"这些能力放在存储层，而不是应用层，意味着任何接入的 Agent 应用都能直接用，不用每个项目单独开发一套文件管理模块。

## 四、改造第三步：日常自动化

图片迁移完成之后，新文章的配图流程变成一条流水线：

写文章 → 脚本把配图传进 Space → 自动生成外链 → 替换 markdown 里的图床地址 → 提交发布。

图片从"发完就忘了"变成"入库即管理"。外链地址是自己桶里的，生命周期自己掌控，不再看第三方图床的脸色。

## 五、前后对比

| 维度 | 改造前 | 改造后 |
|------|--------|--------|
| 图片存储 | 第三方图床，随时可能失效 | 自己的 Space，链接可控 |
| 找图 | 翻文件夹、靠记忆 | AI 按内容检索 |
| 重复图片 | 反复上传没人知道 | 秒传去重，只存一份 |
| 分类管理 | 无 | AI 自动打标签分类 |
| 成本 | 免费但风险自担 | 按量计费，个人站成本极低 |

迁移成本不高：S3 兼容意味着现有代码几乎不用改，改个 endpoint 就能接。Space 的配额和限速是独立的，网站流量再大也不会影响其他业务。
