## 一、产品速览：千问办公是什么

### 1.1 一句话定位

千问办公（QwenWork）是阿里巴巴推出的**一站式 AI Agent 办公平台**，官方口径是：它不做「回答问题」，而是「完成任务」——围绕目标拆解流程、串联工具，把日常办公任务从人工操作升级为 AI 自动执行，并交付可编辑、可交付的成果（Word / Excel / PPT / PDF / HTML / 网页 / 代码 / 图片 / 音视频等）。

### 1.2 上线背景与产品整合

| 维度 | 信息 |
|------|------|
| **正式上线** | 2026-07-27，官网 qwenwork.cn 同步上线，网页端带 BETA 标识 |
| **整合来源** | 由阿里旗下三款智能体产品整合而成：**QoderWork**（桌面级个人生产力）、**悟空**（内嵌钉钉的企业协同）、**MuleRun**（陈宇森带队、主打海外市场） |
| **整合逻辑** | 以 **QoderWork 为技术底座**（用户规模最大、口碑最好、日活/周活/Token 用量在集团所有 AI 工具中第一），叠加钉钉的渠道覆盖（悟空）与前沿能力（MuleRun） |
| **负责人** | 钉钉新任 CEO **陈宇森**（2026 年 6 月接棒后一周内即宣布整合 MuleRun 与悟空，7 月初纳入 QoderWork） |
| **战略意图** | 结束内部赛马、集中火力抢占「AI Native 办公」定义权；对标飞书 aily、腾讯 WorkBuddy/QClaw 等 |

### 1.3 三种使用入口

| 入口 | 形态 | 登录方式 | 能力侧重 |
|------|------|---------|---------|
| **网页端** | 浏览器访问官网 | 钉钉扫码 / 中国大陆手机号验证码 | 云端定时任务、网页全栈制作 |
| **PC 客户端** | macOS 14+（Apple/Intel）、Windows 10+ 64 位 | 同网页端 | 本地文件操作、浏览器自动化、电脑操作（Computer Use） |
| **钉钉内** | 钉钉 PC 端左侧边栏 | 钉钉账号 | 深度绑定钉钉生态（消息/文档/会议/审批/AI 表格） |

### 1.4 能产出什么

- **办公文档**：Word、Excel、PPT、PDF
- **网页与轻应用**：HTML 报告、官网/活动页、数据看板、含增删改查的轻量业务系统（Pages）
- **代码**：桌面客户端可辅助编程
- **多模态**：图片（GPT Image / Nano Banana Pro / Midjourney）、视频（Veo / Kling / Wan / Seedance）、语音（MiniMax Speech）、音乐（MiniMax Music）
- **数据报告**：分析看板、经营复盘、财报/竞品分析

## 二、与通用聊天助手的本质区别

千问办公在官方帮助文档中，给出了与通用聊天助手（如普通 Chat 对话框）的明确区分口径：

| 对比项 | 通用 AI Chat | 千问办公 |
|--------|-------------|---------|
| **核心动作** | 回答问题 | 完成任务 |
| **输出形态** | 以文本答案为主 | 可交付成果（文件/网页/系统操作） |
| **步骤处理** | 用户自行拆解步骤并手动跟进 | 围绕目标拆解流程、串联步骤、调用工具 |
| **工具调用** | 通常无 | 调用文件、连接器、浏览器、本地应用、定时任务 |
| **验收** | 无 | 内置验收标准、人工确认关口 |

一句话总结：**AI Chat 给你「怎么做的建议」，千问办公替你把「做」这件事推进到可交付。**

但这不意味着它「全自动无人值守」——下文会看到，产品在设计上对「可逆/不可逆动作」「人工确认」有非常明确的边界划分。

![](https://raw.githubusercontent.com/CoderWanFeng/img-cdn/master/03-capabilities.png)
### 3.1 重点能力拆解

**① 新任务 / Super Agent（执行模型）**
每次对话是一项围绕目标的任务。执行过程由可展开单元组成：
- **Thinking**：行动前推理摘要
- **Plan**：准备执行的步骤
- **Tool Call**：工具输入输出，多个调用可成一组
- **AskUserQuestion**：缺条件时反问
- **Authorization Card**：敏感动作前请求授权
- **File Result**：生成/修改的文件

单智能体适合单一路径任务；多智能体适合可拆分、需并行研究或交叉验证的复杂任务（行业调研、多材料核验、完整网站制作等），但会增加时间与用量。

**② 电脑操作 Computer Use（最具辨识度的能力）**
- 要求 macOS 14+，需开启**辅助功能**与**屏幕录制**权限
- 三种确认策略：**每次询问**（默认，适合绝大多数）/ **自动执行**（仅低风险已验证流程）/ **禁用**
- 明确**不适用**：CAPTCHA、短信验证码、人脸/二步验证需用户完成；删除、发送、提交表单可能不可撤销
- 原则：网站任务优先用浏览器连接器，只有无合适接口时才用电脑操作

**③ 我的网页 Pages（把产出变成可访问网站）**
- 静态网页：展示页、文档站、纯前端应用
- 动态网页：后端为 Node.js，可挂数据库（每个网页最多一个，挂载后不可换绑）
- 默认域名 `*.qwenwork.host`，支持版本回滚、访问密码
- 自定义域名：文档仍标「即将上线」，且涉及大陆 ICP 备案
- 删除网页会**永久清空关联数据库**，需先导出

**④ 长期记忆 / 意识（Agent 的「人设+记忆」文件）**
目录根 `~/.qwenworkcn/awareness/main`，含：
- `SOUL.md`：协作风格与沟通方式
- `AGENTS.md`：工作规范与行为准则
- `USER.md`：用户画像与偏好
- `MEMORY.md`：跨会话长期知识
- `memory/`：按天短期摘要
两个主开关：**意识模式**（跨会话记忆+技能进化）、**自动记忆**（维护用户画像与记忆反思）。

**⑤ 专家套件 vs Skill vs 连接器（三者关系）**

| 概念 | 主要目的 |
|------|---------|
| **Skill** | 规定 AI 怎么完成一类重复任务 |
| **连接器** | 接入外部账号、应用和数据 |
| **专家套件** | 组合多个 Skill、数据连接、流程与标准，形成岗位/行业方案 |

专家套件可导出为 `.zip` 分享（需含 `.qwen-plugin/plugin.json` 或 `.claude-plugin/plugin.json`），公开内置方向含：产品与设计、法律与财税、咨询与营销、投资与金融、科技服务。

## 四、模型与套餐体系

![](https://raw.githubusercontent.com/CoderWanFeng/img-cdn/master/04-models-pricing.png)

### 4.1 模型档位

| 档位 | 特点 | 推荐任务 |
|------|------|---------|
| **基础 Basic** | 智能高效，规则清楚 | 简单问答、格式转换、文案润色、信息整理、模板邮件 |
| **高级 Advanced** | 强劲均衡，质量稳定 | 关键分析、研究报告、复杂方案、长文、多步骤工作流 |
| **Qwen3.8-Max-Preview** | 当前文档列出的通义千问高阶预览模型 | 进阶推理、复杂求解、高质量长文 |

> 背景补充（公开新闻）：阿里千问旗舰模型 **Qwen3.7-Max** 在 Artificial Analysis 榜单位列全球第五、中国第一，专为 Agent 场景设计，可自主编程与工具调用完成超 1000 次工具调用的长程任务。文档中的 `Qwen3.8-Max-Preview` 为更高阶预览名，是否长期保留以账号界面为准。

**同任务内可切换模型**：资料收集/格式整理用基础，复杂分析切高级/预览，最终格式化再切回基础；切换前建议让 Agent 总结目标与已确认事实以降低偏差。

### 4.2 个人套餐（摘自文档，价格高时效）

| 套餐 | 可发布网页数 | Web 访问密码 | Web 数据库 |
|------|------------|-------------|-----------|
| **免费版** | 5 | 不支持 | 不支持 |
| **个人标准版** | 10 | 支持 | 支持 |
| **个人高级版** | 50 | 支持 | 支持 |

企业侧另有席位、组织共享积分池、连接器和团队知识库（企业管理页在抓取时返回 404，角色矩阵未补全，不视为已开放证据）。

### 4.3 积分消耗因素（7 项）

模型档位、上下文长度、文件数量与大小、输出长度、工具调用次数、多智能体、重复执行。减少无效消耗的方法：
1. 一个任务只保留一个清晰目标
2. 只附加当前阶段相关文件
3. 写清输出格式、篇幅、禁止事项
4. 复杂任务先确认计划/大纲
5. 长对话完成一阶段先总结
6. 定时任务先手动跑一次看单次积分
7. 结果不理想先查输入与验收，不立即反复换模型

> 成本提示（来自 QoderWork 评测）：Qwen 顶尖模型在 **22:00–08:00** 有夜间折扣；Qwen3.7-Plus 为多模态且费用最低，常被夜间办公选用。

## 五、产品内置的工作方法论



这是 qwenwork.org 最有价值的部分——它不只教「点哪里」，而是提炼了一套可复用的**工作分解与治理方法**。

![](https://raw.githubusercontent.com/CoderWanFeng/img-cdn/master/05-maturity.png)

### 5.1 通用任务模板（5+ 要素）

```
目标：我要交付什么，给谁使用。
输入：可使用哪些文件、链接和背景资料。
范围：必须包含什么，不要做什么。
格式：文件类型、结构、语言、篇幅和命名方式。
事实规则：哪些信息必须引用，缺失时如何标记。
验收：用哪些可检查条件判断完成。
安全：哪些操作需要先询问或授权。
```

### 5.2 四级成熟度（L1–L4）

| 等级 | 工作方式 | 进入下一级条件 |
|------|---------|---------------|
| **L1 单次辅助** | 人供材料，AI 生成草稿 | 结果可验收并连续成功三次 |
| **L2 固定模板** | 标准输入输出结构 | 字段、规则、责任人稳定 |
| **L3 工作流** | Skill+连接器+定时任务协作 | 有日志、异常处理和停用方法 |
| **L4 团队能力** | 部门共享、权限与资产治理 | 成本、权限、质量、变更流程完备 |

低频、差异大或责任重的任务不必追求 L4，保持「AI 辅助 + 人工决策」更可靠。

### 5.3 Skill：把一次成功变成可复用能力

Skill **不是模型、也不等于外部工具**，而是一份交给千问办公的「专业工作说明书」——规定触发条件、输入、步骤、工具、输出标准、边界与异常处理。

**从一次成功创建 Skill** 的推荐提示：
```
请把刚才的流程整理为一个可复用 Skill。
必须写清：
1. 适用和不适用场景；
2. 开始前需要的输入；
3. 按顺序执行的步骤；
4. 可以调用的工具与权限；
5. 输出结构和验收标准；
6. 信息不足、工具失败或高风险操作时的处理方式。
不要保存本次任务中的个人数据、临时账号或业务机密。
```

内置示例 Skill：`pptx` / `xlsx` / `docx` / `pdf`（办公文件）、`find-skills`（找技能）、`create-skill`（建技能）、`plugin-creator`（建专家套件）、`qwenwork-guidance`（查设置/连接器/任务/额度）。

### 5.4 场景需求模板 & 行业/部门工作流卡

**场景需求模板（调研类）**：
```
研究问题：要支持哪项决策？
范围：行业、对象、地区与时间窗口。
来源：优先来源、排除来源、需登录平台。
输出：结论、证据链接、日期、冲突信息和未知项。
验收：关键结论至少由几个独立来源支撑。
```

**行业工作流卡**：
```
行业对象：[订单、合同、课程、内容等]
参与岗位与系统：[角色、数据源、交接点]
关键口径：[字段、版本、日期、单位]
候选步骤：[重复、耗时、可验收的环节]
错误影响：[财务、合规、客户或安全影响]
人工责任：[确认人、停止条件、升级路径]
```

## 六、场景与落地实践

### 6.1 五类业务链（场景实战）

| 场景 | 核心链路 | 建议首个试点 |
|------|---------|-------------|
| **电商** | 数据与选品 → 商品素材 → 经营复盘 | 一个品类、一个平台、十个候选商品 |
| **闪购** | 上下架 → 活动测算 → 商品诊断 → 视觉升级 | 一家门店、一周数据、一次活动 |
| **教育** | 内容体系 → 教学/学习材料 → 反馈调整 | 一节课或一个知识单元 |
| **营销** | 热点策划 → 多平台素材 → 分发 → 复盘 | 一个主题、两个渠道、一个周期 |
| **咨询** | 客户材料 → 行业对标 → 风险诊断 → 报告 | 一个问题、一个数据包、一次评审 |

开始前的共同约束（6 条）：说清业务决定、标注输入来源与缺失、拆分读取/生成/写入/发布/删除的授权阶段、小样本验证、对数字与不可逆操作设人工确认、验收后再沉淀为模板/Skill/定时任务。

### 6.2 案例库规模

| 类型 | 数量 | 说明 |
|------|------|------|

## 七、安全与治理设计

千问办公在文档中对「权限、确认、可逆性、专业责任」有贯穿性的强调，这是其区别于「纯聊天玩具」的关键设计取向。

### 7.1 权限边界

- **不会自动提权**：可访问钉钉/连接器内容，由当前账号原有权限、企业配置、用户授权与接口能力共同决定；使用千问办公不会自动提升权限
- **授权后可能执行真实动作**：协助发送消息、生成/写入文档、发起审批、公开发布、删除文件——执行前必须核对对象、内容、范围
- **连接器数据范围**：取决于连接器能力、实际账号与授权范围；安装前检查服务提供方、读写权限、传输范围与撤销方式

### 7.2 人工确认关口（按风险分级）

| 动作类型 | 处理原则 |
|---------|---------|
| 读取/整理 | 通常可直接执行 |
| 生成草稿 | 可自动，发布前确认 |
| 写入/发送/审批 | 需明确确认对象与范围 |
| 删除/覆盖/发布/支付/权限变更/批量写入 | **不得使用无人值守自动执行** |

电脑操作确认策略同样分级：每问（默认）/自动（仅低风险已验证）/禁用。

### 7.3 专业责任排除

文档明确：医疗、法律、投资、财税、合规和重要经营事项，**必须由具备相应责任或资质的人复核**，AI 结果不直接作为决策依据。涉及法律、财税、投资或人事判断的套件不能代替专业复核。

### 7.4 记忆治理与备份

- 不把一次性账号、密钥、访问令牌写进长期记忆
- 事实、偏好、推断分开记录并保留来源与更新时间
- 清空记忆/重置工作手册前先导出备份，确认无密钥/密码/敏感信息
- 重要决策不因「系统记得」就跳过原始材料核验

## 九、创作者启示与普通人用法

### 9.1 可写的选题角度（8 个）

## 十、关键结论与风险提示

### 10.1 核心结论

1. **千问办公是阿里「AI Native 办公」的集大成产品**，底座 QoderWork 已是集团 AI 工具中用户与 Token 规模最大的，整合后资源集中、商业化意图明确。
2. **能力广度领先**：电脑操作、Pages 网页发布、专家套件、钉钉深度集成，构成了从「对话」到「交付」的相对完整闭环。
3. **方法论是隐藏资产**：qwenwork.org 提炼的任务模板、四级成熟度、Skill/专家套件、行业工作流卡，本质是一套「非技术岗如何用好 Agent」的操作规范，价值不亚于工具本身。
4. **治理取向成熟**：权限边界、人工确认、专业责任排除贯穿文档，说明产品定位是企业级而非玩具。

### 10.2 风险提示（务必注意）

| 风险 | 说明 |
|------|------|
| **粉丝站非官方** | qwenwork.org 是第三方指南，产品能力以 qwenwork.cn 为准；本文亦以此为据，非官方承诺 |
| **早期 BETA** | 2026-07-27 刚上线，网页端 BETA，功能/套餐/入口变化快 |
| **待开放功能** | 自定义域名、Pages 桌面端创建、部分企业管理能力仍「即将上线」或 404 |
| **端差异大** | Web/桌面/钉钉功能不同，定时任务两端不互通、不补跑 |
| **信息高时效** | 模型名、价格、积分规则以当前账号界面为准，文档可能滞后 |
| **专业责任** | 医疗/法律/投资/财税/合规事项须人工复核，AI 不替代决策 |
