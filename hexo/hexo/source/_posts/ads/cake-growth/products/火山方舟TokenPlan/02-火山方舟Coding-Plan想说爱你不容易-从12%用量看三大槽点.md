我买了火山方舟的 **API Live Coding Plan**，办了一张"程序员晚枫专属"的截图给你们看：

![火山方舟 Coding Plan 后台](https://raw.githubusercontent.com/CoderWanFeng/img-cdn/master/20260725211316192.png)

看完这个数据，我想说：

**火山方舟的 Coding Plan，想说爱你，真的不容易。**

下面我就要不客气了，主要吐 3 个槽点。

---

## 槽点 1：用了一个月，才用了 12%——这额度是不是有点太多了？

**近 1 月用量 12%，近 1 周 24%，当天 98%。**

看到这个数据组合，我人都傻了。

我当时买这个 Coding Plan 的初衷，是想用作日常开发的辅助：

- 让 AI 帮我写代码
- 让 AI 帮我解释一段不懂的代码
- 让 AI 帮我 review 代码
- 让 AI 帮我补注释

按理说，**这是一个高频使用场景**。

但我实际用了 1 个月：

- 第一个月配额大概够用 8 个月
- 我平时用得最频繁的时候，单日也只有 98%
- 平时一周下来，平均只用 24%

**也就是说：** 我买的这个套餐，大概**只能用到 1/8**。

剩下的 7/8 都浪费了。

**我付了一个月的钱，却用了 1/8 的额度。**

你说我要不要心疼？

### 用量少的根源：基础模型太弱，没动力去用

为什么我平时用得少？

我后来反思了一下：

**不是不想用，是真的没什么动力去用。**

为什么？

因为 Coding Plan 默认带的那个模型（默认是 **GLM-5.2 Pro** 或者某个老版本），回答问题经常是这样：

- 写的代码不够聪明
- 回答问题逻辑混乱
- 长上下文记不住
- 一个简单的需求改 3 遍还是不对

**用着用着，就觉得烦了，最后还是切回别的工具。**

如果 Coding Plan 里能直接接入**真正顶级的模型**（比如 Kimi K3、Claude Sonnet 4.5、GPT-5.5 这种级别），我相信我会高频使用。

但很可惜，**Coding Plan 里能选的模型，普遍不是第一梯队**。

**这就引出了我要吐的第二个槽点。**

---

## 槽点 2：模型更新慢——上次模型更新是哪天？

兄弟们，你们知道 Coding Plan 上次更新模型是什么时候吗？

我记得我开通的时候（约 2026-05-21），Coding Plan 里能选的主流模型大致是：

- GLM-5.2 系列
- 豆包 2.0 系列
- 早期的 Doubao 系列

**3 个月过去了。**

这 3 个月里，外面发生了什么？

- 火山引擎发布了 **豆包 2.1 Pro**（FORCE 大会上）
- Kimi K3 登顶 arena.ai 的 WebDev 榜
- Claude Sonnet 4.5 出来了
- GPT-5.5 也迭代了

**但 Coding Plan 里呢？**

主流可用的模型，还是那几款老面孔。

**等了 3 个月，模型基本没怎么动。**

### 真实体验：我用 Coding Plan 里的模型写了一个 Demo，结果……

我前两天用 Coding Plan 里的一个模型，让它帮我写一个简单的 Python 脚本：

> "用 FastAPI 写一个用户登录接口，要支持 JWT"

你猜它给我的代码长什么样？

```python
# 给我的代码（部分）
from fastapi import FastAPI, Depends, HTTPException, status
from fastapi.security import OAuth2PasswordBearer
from jose import JWTError, jwt
import ...

# 这段代码需要 jose 库，但 jose 已经 3 年没更新了
# 而且这个模型完全不知道 fastapi 0.100+ 之后 OAuth2PasswordBearer 的参数已经变了
```

我用这个代码直接跑——报错。

我让它修一下，它改了 3 遍，还是有问题。

最后我**切回 Claude**（直接在 Anthropic 官网用），一版就 OK 了。

**这就是 Coding Plan 模型的真实水平：能给你东西，但很难一次给你能用的东西。**

如果是顶级模型，可能一版就 OK 了。

**差的不是价格，差的是能力。**

---

## 槽点 3：可选模型不多——想用顶级的，对不起，没有

兄弟们，你们猜 Coding Plan 现在能选多少款模型？

我数了一下：

- GLM-5.2 / GLM-5.2 Turbo
- 豆包 2.0 系列
- 早期的 Doubao 系列
- 一些定制版

**主流能用的，也就 4-5 款。**

而且这里面：

- 没有 **Claude Sonnet 4.5**（Anthropic 的旗舰）
- 没有 **GPT-5.5**（OpenAI 的旗舰）
- 没有 **Kimi K3**（国产 WebDev 第一）
- 没有 **Gemini 3.1 Pro**（Google 的旗舰）

**你想要的"好模型"，一个都没有。**

### 为什么可选模型这么少？

我能猜到的原因：

1. **字节自家没有 Claude 这种级别的"独门"模型**
2. **豆包虽然跑得快，但编码能力真的不是第一梯队**
3. **接入第三方模型（如 Kimi、Claude），可能涉及到商业分成问题**

但不管原因是什么，**对消费者来说，事实就是：你花了钱，但只能选"次等"的模型。**

---

## 但为什么我还是买了？

吐槽归吐槽，我要说一个**重要的公平话**：

**Coding Plan 也不是一无是处。**

它的几个优点是：

1. **国内访问稳定**——毕竟是字节自家的服务，比直接访问 Claude 稳
2. **价格便宜**——一个月几十块，比单独买 API 便宜
3. **能直接用 GLM-5.2**——这个模型在编码领域其实还可以
4. **支持 Skills / Agent**——和 Trae / Coze 等工具能打通

**但如果它的模型能更顶级、更新更勤快、选项更多，我愿意付 2 倍的钱。**

可惜，目前它做不到。

---

## 我的建议：什么情况下买 Coding Plan，什么情况下别买？

### 建议买：
- ✅ 你主要在国内使用 AI 编程，**不在乎是不是顶级模型**
- ✅ 你主要做一些简单任务（写注释、补文档、改小 bug）
- ✅ 你想要稳定的国内服务，**不在乎跑分**

### 建议别买：
- ❌ 你追求**顶级的编程能力**（选 Claude Code + Sonnet 4.5）
- ❌ 你想做**复杂的架构设计**（选 Kimi K3 或 Claude Opus）
- ❌ 你对**模型更新速度**有要求（选 Cursor 或 Copilot 这种紧跟主流的）
