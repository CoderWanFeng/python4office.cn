## 2. OpenAI 公司画像

### 2.1 使命与宪章

**核心使命**：确保通用人工智能（AGI）造福全人类。

> "OpenAI 是一家人工智能研究和部署公司。我们的使命是确保通用人工智能造福全人类。"
> — 关于页面

**宪章四大原则**（来源：/charter/）：

| 原则 | 核心承诺 |
|------|---------|
| **广泛利益** | AGI 的部署应惠及全人类，避免有害应用或权力过度集中；对人类的受托责任高于一切 |
| **长期安全** | 投入安全研究并推动全行业采纳；若其他安全项目接近 AGI，承诺停止竞争转而协助 |
| **技术领导** | 必须处于 AI 能力前沿，仅靠政策倡导不足以应对 AGI 影响 |
| **合作导向** | 积极与其他机构合作，创建全球社区共同应对 AGI 挑战；发布公共产品帮助社会导航 AGI 之路 |

> ⚠️ 宪章原文为英文，中文版网站未翻译宪章页面。这反映了 OpenAI 在国际化策略中，将核心治理文件保留英文原版的原则。

### 2.2 组织架构

**2025 年 10 月 28 日资本重组后的结构**：

```
OpenAI Foundation（非营利机构）
    │
    ├── 治理和控制 ──→ OpenAI Group PBC（营利性公共利益公司）
    │
    └── 持有 26% 股权（约 1,300 亿美元）
```

**关键特征**：

| 维度 | 说明 |
|------|------|
| **非营利机构** | 更名为 OpenAI Foundation，保留治理权 |
| **营利性机构** | OpenAI Group PBC，以公共利益公司形式运营，须兼顾使命与商业利益 |
| **治理关系** | Foundation 控制 Group，可任命/更换 Group 全部董事 |
| **安全委员会** | 安全与保障委员会（SSC）隶属于 Foundation，对全部 OpenAI 机构行使安全治理权 |
| **股权激励** | Foundation 持有认股权证，若 Group 股价 15 年内涨超 10 倍，Foundation 将获得大量额外股权 |

## 4. GPT-5.6 深度解析

> 来源页面：`/zh-Hans-CN/index/gpt-5-6/`（18 分钟阅读）

### 4.1 三模型层级

GPT-5.6 系列包含三个持久能力层级，可独立演进：

| 模型 | 定位 | 输入价格 | 输出价格 | 对标 |
|------|------|---------|---------|------|
| **Sol** | 旗舰，行业前沿 | $5/M tokens | $30/M tokens | Claude Fable 5、Gemini 3.1 Pro |
| **Terra** | 均衡，性能≈GPT-5.5 且更便宜 | $2.50/M tokens | $15/M tokens | Claude Opus 4.8 |
| **Luna** | 高速、高性价比 | $1/M tokens | $6/M tokens | Gemini 3.5 Flash |

### 4.2 推理强度模式

| 模式 | 机制 | 适用场景 |
|------|------|---------|
| **默认** | 高效运作，编写轻量程序，协调工具 | 日常任务 |
| **max** | 更多推理时间，探索替代方案，执行校验 | 复杂分析、多步推理 |
| **ultra** | 并行协作 4 个智能体（可扩展至 16），跨多工作流协调 | 最具挑战的任务 |

### 4.3 六大核心能力

#### 4.3.1 编程能力

| 评测 | GPT-5.6 Sol | GPT-5.5 | Claude Fable 5 | 说明 |
|------|-------------|---------|----------------|------|
| Artificial Analysis Coding Agent Index v1.1 | **80**（新 SOTA） | 76.4 | 77.2 | 比 Fable 5 高 2.8 分，Token 减半、耗时减半 |
| Terminal-Bench 2.1 | 88.8% / **91.9%**（ultra） | 85.6% | 83.1% | 行业顶尖 |
| DeepSWE v1.1 | 72.7% | 67% | 69.7% | 代码工程任务 |

> 客户反馈：Cursor 总裁 Oskar Schulz 称 GPT-5.6 是"CursorBench 上测试过的能力最强的模型之一"。

### 5.2 Agents SDK vs Responses API

| 维度 | Responses API | Agents SDK |
|------|---------------|-----------|
| **最佳场景** | 自定义模型驱动功能和工作流 | 有界对话/事务工作流 |
| **核心抽象** | 模型响应 | 智能体运行 |
| **工具** | 平台工具、函数调用、远程 MCP | 可复用智能体 + 工具包装器 + 本地 MCP + 智能体即工具 |
| **编排** | 自定义循环和分支 | SDK 提供智能体循环和生命周期 |
| **多智能体** | 自建路由和委托 | 内建智能体即工具和交接 |
| **状态** | 手动历史/响应链 | SDK 会话 + 可恢复运行状态 |
| **安全/审批** | 工具级审批 | 输入/输出/工具护栏 + 可恢复审批流 |
| **调试/追踪** | 响应对象和 API 日志 | 内建跨模型调用/工具/智能体/护栏的追踪 |

**SDK 功能矩阵**：

| 功能 | 入口 | 用途 |
|------|------|------|
| 快速入门 | Quickstart | 最短路径跑通一个智能体 |

| 模型与提供商 | Models & Providers | 模型选择、提供商设置、传输策略 |
| 运行智能体 | Running Agents | 智能体循环、流式传输、续接策略 |
| 沙箱 | Sandbox Agents | 文件、命令、包、快照、挂载 |
| 编排与交接 | Orchestration | 多智能体归属权管理 |
| 护栏与人工审核 | Guardrails | 验证、暂停、审批 |
| 结果与状态 | Results | 最终输出、可恢复状态 |
| 工具使用 | Using Tools | 平台工具、函数工具、MCP |
