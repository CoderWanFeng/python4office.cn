大家好，我是程序员晚枫。

很多人想做个人网站，真正卡住的往往不是写内容，而是开始之前的一串问题：

- 写博客应该选 Hexo、Hugo，还是别的框架？

- 网站文件应该放在哪里？

这些问题每一个都不算难，但连在一起，就足以让人把建站计划一拖再拖。

所以我把自己的建站流程整理成了一个 Skill：**让 AI 不只告诉你怎么做，而是在你确认之后，按流程把项目真正创建出来。**

## 一、这个 Skill 能做什么？

它内置了 5 类常见的个人网站，也保留了自定义需求入口。

| 网站类型 | 默认方案 | 适合场景 |
|---|---|---|
| 个人博客 | Hexo + Butterfly | 写文章、记录生活、长期更新内容 |
| 知识库 | VitePress | 教程、文档、学习笔记、项目说明书 |
| AI 导航网站 | Vue 3 + Vite + Vue Router | 分类展示 AI 工具和资源 |
| 个人作品集 | 纯静态 HTML + CSS | 展示项目、设计、摄影或其他作品 |
| 个人简历站 | 单文件 HTML + CSS | 在线简历、个人介绍、打印为 PDF |
| 自定义网站 | 根据需求推荐 | 博客加作品集、工具导航加博客等组合需求 |

你不需要先记住这些技术名词。

如果你说“我想长期写文章”，它会推荐 Hexo；如果你说“我想整理一套教程”，它会推荐 VitePress；如果你只是想做一个作品展示页，它不会再给你套一个复杂框架。

**技术栈是手段，网站用途才是起点。**

## 二、从需求到预览，一共 5 个阶段

这个 Skill 采用纯对话式引导，不弹窗，也不要求你填写一张很长的表单。

### 第 1 步：确认网站类型

你可以直接说“我要做个人博客”或“帮我做一个简历站”，不用从菜单开始。

Skill 会识别你的需求，先确认它理解得对不对，再继续下一步。

### 第 2 步：确认技术栈

它只展示与你所选网站有关的方案，并给出默认推荐。

例如选择个人博客后，才会看到 Hexo、VuePress、Hugo 等选项，而不是一开始就把所有框架堆到你面前。

不懂怎么选，可以跟随推荐；有明确偏好，也可以直接指定。

### 第 3 步：收集网站信息

它会分别询问：

- 网站名称
- 一句话网站描述
- 作者名
- GitHub 用户名（博客、知识库和 AI 导航需要，可留空）

这些信息会用于网站标题、SEO 描述、署名、版权信息和社交链接。

没有提供的信息会使用明确的占位符或跳过，不会擅自给你编一个真实人物身份。

### 第 4 步：选择创建目录

你可以在当前目录下新建 `my-website`，也可以换一个子目录名，或者指定一个绝对路径。

项目始终创建在新的子目录中，不会直接初始化到你指定的父目录里。

如果同名目录已经存在，它会自动尝试 `-2`、`-3` 这样的后缀，而不是直接覆盖原有文件。

### 第 5 步：汇总确认，再执行创建

真正动手之前，你会看到一份完整清单：网站类型、技术栈、名称、描述、作者和创建目录。

只有你回复“确认”或“yes”，它才会执行。

创建完成后，它会安装所需依赖、启动本地预览，并在有图形界面的环境中自动打开浏览器。博客和知识库还会附带中文使用指南及英文入口，告诉你下一篇文章写在哪里、常用命令怎么运行。

**不是只生成一堆文件，而是让你马上看到网站，并知道接下来怎么改。**

## 三、想让别人访问，还可以继续部署

本地预览之后，Skill 会询问你是否继续部署。你可以选择暂时保留在本地，也可以从下面 6 个平台中选择：

| 平台 | 特点 | 使用前需要知道的事 |
|---|---|---|
| Netlify | 支持匿名部署，操作少 | 匿名站点是临时的，7 天后过期，保留需要绑定账号 |
| Surge.sh | 命令简洁 | 国内访问可能较慢 |
| Cloudflare Pages | 适合长期使用 | 需要 API Token，权限要按文档配置 |
| 腾讯云 CloudBase | 国内访问更方便 | 需要环境 ID，首次使用还要在控制台开通环境 |
| Vercel | 部署流程成熟 | 需要登录，海外节点在国内访问可能受影响 |
| GitHub Pages | 免费托管静态网站 | 需要 GitHub CLI，并已登录 |

它还会检查当前环境里已经安装了哪些部署工具，再给出推荐。部署命令、环境变量和需要替换的参数，不要凭空猜，按照对应平台的文档填写即可。

这里我想特别说明：**“支持部署”不等于所有平台都能无条件一键上线。**

需要账号的平台仍然要登录，需要 Token 或环境 ID 的平台仍然要由你提供。Skill 做的是把流程串起来，不是绕过平台本身的规则。

## 四、为什么把它做成 Skill，而不是只给你一段提示词？

因为建站不是生成一段回答就结束了。

这个 Skill 除了对话流程，还包含真实的项目模板、初始化脚本、预览脚本、部署脚本和故障排查文档。

几个我觉得很实用的细节是：

1. **路径安全校验**：拒绝根目录、系统目录和包含越界风险的路径。
2. **目录重名处理**：自动选择新的子目录名，降低覆盖旧项目的风险。
3. **创建前强制确认**：AI 不能跳过清单直接执行。
4. **自动打开预览**：创建后尽量直接进入可查看的网站，而不是停在终端里。
5. **部署结果验证**：部署后会检查 URL 是否可访问，并保存状态，方便后续重新部署。
6. **附带入坑文档**：Node.js 版本、依赖安装失败、网络问题等，都有对应的排查说明。

对于 Hexo、VitePress 和 Vue 3 项目，建议使用 **Node.js 18 或更高版本**；作品集和简历站是纯静态 HTML，不需要先安装前端框架。

## 六、它适合谁，又不适合谁？

它比较适合：

- 第一次做个人网站，不知道从哪里开始的人；
- 想写博客、整理知识库，却不想先研究框架的人；
- 需要快速制作作品集或在线简历的人；
- 想做一个 AI 工具导航站的人；
- 已经有想法，希望 AI 把重复建站流程跑完的人。

它不太适合：

- 需要复杂后端、账号系统、支付系统的应用；
- 已经有成熟网站，只想做局部改版的人；
- 对项目结构有非常具体要求，希望全部手工实现的人；
- 不愿意检查配置，也不愿意处理平台登录和部署凭证的人。

它不是“任何网站都能自动生成”的万能工具，而是把**常见静态个人网站的创建流程**整理成了一条可以重复执行的路。
