> **一句话总结**：看到一篇好文章想存下来，Ctrl+S 存出来的是一堆散文件和断掉的图片链接。这个 Skill 给你**一个文件，双击就能看**。

大家好，我是程序员晚枫。

做自媒体的人都有个习惯：**看到好文章，存一下。**

万一哪天要用呢？万一它被删了呢？

但你真去存的时候会发现，**公众号文章特别难存**。

在 Chrome 里按 Ctrl+S「另存为网页」，出来的是：

```
某公众号某文章.files/
├── 1.dat
├── 2.dat
├── 3.dat
├── ...（几百个）
└── 某公众号某文章.html
```

**图片是一堆 .dat 文件，链接是相对的。** 换台电脑、隔天再打开，图裂一半。

那怎么办？装个「网页另存为」插件？装个浏览器自动化工具？——为了存一篇文章，**下载 150MB 的 Chromium。**

我一开始也这么干。但用了一段时间我发现，这事可以做得更轻。

所以我写了「公众号保存侠（mp-saver）」：**不登录、不装浏览器，一个文件存完。**

**SkillHub 发布页**：[公众号保存侠：https://skillhub.cn/skills/user_bf8c5b73/wanfeng-mp-saver](https://skillhub.cn/skills/user_bf8c5b73/wanfeng-mp-saver)

## 一、v2.0 最大的变化：把 Chromium 扔了

| | v1.x | v2.0 |
|---|---|---|
| **依赖** | Playwright + Chromium（约 150MB 下载） | **Python 标准库（0 第三方包）** |
| **启动速度** | 5–10 秒（浏览器冷启动） | **< 1 秒** |
| **安装耗时** | 1–2 分钟（含 Chromium 下载） | **0.1 秒** |
| **单篇耗时** | — | **秒级** |

**为什么能扔？** 因为公众号文章**不需要渲染就能拿到完整 HTML**。

那篇文章在浏览器里看到的排版，本质是服务端返回的一段 HTML + 一堆 CSS。**你只要把这段 HTML 原样拿下来，再把图片转成 base64 塞进去，得到的文件跟「另存为网页」完全等价。**

**而且更快、更稳，还不会被页面改版搞挂。**

## 二、它到底做了什么

```
urllib 抓 HTML（带 WeChat UA + Referer）
  → 反爬兜底页检测（抓到了假页面就报错退出）
  → 从 og:title 提取标题
  → unlazy 修补（把 data-src 提到 src）
  → 下载所有图片转 base64 内嵌
  → 加 <base href> 防止相对资源 404
  → 写出单个 .mhtml 文件
```

有几步是外行看不太懂但很关键的：

**og:title 提取标题。** 不用解析正文去找 `<h1>`，直接读页面头里那个 `og:title`——**这是页面自己声明的标题，最准**。而且文件名自动用它，省得你手动改。

**unlazy 修补。** 公众号的懒加载图片，真实地址藏在 `data-src` 里，`src` 上放的是占位图。**不修补的话你存下来就是一片空白。**

**加 `<base href>`。** 这步是为了让那些没被内嵌的远程图片还能正常显示——**加上它，相对路径就以原文章为基准解析了，不会 404。**

## 三、三种输出，你选

### A · MHTML 限 200 张内嵌（默认推荐）

```bash
python3 scripts/save_mp.py --format mhtml --max-images 200 "https://mp.weixin.qq.com/s/xxx"
```

- 单文件，**前 200 张图 base64 内嵌**
- 其余图片保留远程 URL，打开时自动加载
- 体积：**5–50MB/篇**

### B · MHTML 全部内嵌

```bash
python3 scripts/save_mp.py --format mhtml --max-images 0 "https://mp.weixin.qq.com/s/xxx"
```

- 所有图片 base64 内嵌，**完全离线可看**
- 体积：**20–100MB/篇**

### C · 纯 HTML

```bash
python3 scripts/save_mp.py --format html "https://mp.weixin.qq.com/s/xxx"
```

- 不下载图片，**最快（5 秒/篇）**
- 体积：100–500KB
- 代价：**离线看不到图**

### 为什么默认是 A？

我实测过一篇文章，**490 张图**。

全内嵌的话，base64 编出来 **77.6MB**，下载占 150MB——**分享一次都费劲**。

限 200 张的话是 48MB，**打开能看完整正文**，后面的图联网加载。**这个平衡点是我试出来的，不是拍脑袋。**

## 四、批量存，自动出清单

```bash
python3 scripts/save_mp.py \
  --output /Users/wanfeng/Desktop/mp-saves/ \
  --slug "7月AI日报" \
  "https://mp.weixin.qq.com/s/aaa" \
  "https://mp.weixin.qq.com/s/bbb" \
  "https://mp.weixin.qq.com/s/ccc"
```

跑完目录长这样：

```
mp-saves/20260813-ai-daily/
├── index.md                    ← 清单（标题/大小/链接/失败项）
├── cursor-深度评测.mhtml
└── claude-code-使用心得.mhtml
```

**清单里有一栏「失败清单」。** 哪篇没存下来、为什么，都在清单里写着，不会悄悄漏掉一篇。

## 五、它是怎么认出「这一篇是假的」

公众号的反爬，有三种情况会让你抓回来的根本不是文章，而是**兜底页**：

| 兜底页特征 | 它的处理 |
|---|---|
| URL 跳到 `wappoc_appmsgcaptcha` | 报错退出，提示「用浏览器手动另存为」 |
| HTML 小于 30KB，且含「环境异常」「验证身份」「请完成验证」 | 报错退出 |
| 没有图床域名（`mmbiz.qpic.cn`），且含「该公众号已被屏蔽」「该文章已被发布者删除」 | 报错退出 |

**这里有个坑我必须说，因为我自己踩过：**

> v1 用「请在微信中打开」当兜底标记。**结果所有文章都被判成假的。**

原因很隐蔽：**这串字出现在公众号所有页面的 JS 检测脚本里**，真文章也会命中。**结果是 100% 误判。**

v2.0 换掉了这个判据，改成看域名、看体积、看真实错误文案。

**这就是为什么要写工具而不是一直手动操作**——手动存的时候，你一眼就知道「这页不对」，但脚本会一本正经地告诉你「保存成功」。

## 六、抓不到的时候，它会好好说话

这是我觉得做得很到位的一点：**报错不是甩一句堆栈给你看。**

它按 5 段式回答：

1. **原文** —— 贴出报错最后 1-2 行
2. **人话** —— 一句大白话解释发生了什么
3. **根因** —— 技术层面的真正原因
4. **3 步** —— 你能立刻执行的 3 个具体动作
5. **兜底** —— 它无能为力时的退路（手动另存为）

**「报错要能让人知道下一步干什么」——这个标准我觉得对所有工具都适用。**

## 七、它能做什么，不能做什么

| 行为 | 做不做 | 说明 |
|---|---|---|
| 不登录任何账号 | ✅ | **核心原则** |
| 存 `mp.weixin.qq.com/s/...` | ✅ | 唯一支持的 URL 模式 |
| 存其他域名的文章 | ❌ | 知乎、简书、普通博客一律拒绝 |
| 存「仅关注后查看」的文章 | ❌ | 抓不到正文，会报兜底页 |
| 存含视频号视频的文章 | ⚠️ | **视频仍是远程 URL**，离线看不了 |
| 装 150MB 的 Chromium | ❌ | v2.0 起不装任何第三方包 |
| 自动转 Markdown | ❌ | 它只做保存，不做下游联动 |

**URL 校验很严格**：只接受 `https://mp.weixin.qq.com/s/...`。别的域名、非 `/s/` 路径、空链接、非 http 协议，全部拒绝。

> **为什么要这么严？** 因为它是「看到链接就存」的工具，**一个手滑贴错的 URL 不该变成一个莫名其妙的任务目录**。

## 八、还有个隐藏用法：喂给别的 Skill

这是我觉得它真正的潜力。

它的产物是 `.mhtml`，而 `.mhtml` 正好是 **MarkItDown**（我之前写过那篇）能吃的格式。

所以链路是：

```bash
# 第一步：保存
python3 scripts/save_mp.py --output ./saved "https://mp.weixin.qq.com/s/xxx"

# 第二步：转成 Markdown
bash doc-speedreader/scripts/convert.sh ./saved/xxx.mhtml
```

**一篇公众号文章 → 一个可搜索、可喂给 AI 的 Markdown 文件。**

这个组合对做知识管理的人挺有用：**你收藏的所有好文章，可以变成一个本地知识库。**
