> **一句话总结**：录好的口播视频，底下就是一张脸和几行字。它读你的口播稿，**在讲到哪句，就把对应的卡片弹到哪**。

大家好，我是程序员晚枫。

你录了一条口播视频，人在中间讲，画面上除了字幕就是空白。

**这种片子的问题不是难看，是「平」。** 观众的眼睛没有地方落，看完记住了你说的内容，但记不住你的画面。完播率也就上不去。

想加东西？加个数据卡、加个对比框、加个清单弹窗——**但你不会做动效，也不想学 AE、Pr。**

所以我做了「晚枫自动剪辑（mograph）」。

它的输入很简单：**一条口播视频 + 一份口播稿**。输出是：**在人的四周（或身前）按讲话内容定时弹出动效卡片**的成片。

**SkillHub 发布页**：[晚枫自动剪视频：https://skillhub.cn/skills/user_bf8c5b73/wanfeng-mograph](https://skillhub.cn/skills/user_bf8c5b73/wanfeng-mograph)

## 一、它最有意思的一个设计：故意不带素材库

别的动效工具都会在安装包里塞一堆动效模板。**这个 Skill 反着来——它一个素材库都不带。**

理由很实在：**Remotion、HyperFrames 这些社区每个月都在长新的卡片实现，你硬编码进 Skill，就是给自己造一堆过期库存。**

所以它只沉淀**三件不会过期的东西**：

| 沉淀什么 | 为什么不会过期 |
|---|---|
| **位置语义** | 人脸在哪、卡片该往哪放，这是物理 |
| **时间轴契约** | 卡片在第几秒出现、持续多久，这是结构 |
| **检索协议** | 怎么联网找到社区最新的实现，这是方法 |

**「找最新实现」这一步，交给使用者本地的 AI 在运行时联网完成。**

第一次运行要多花 3–8 分钟联网检索；收益是**你永远用的是社区最新的版本，不用追库存**。

## 二、三层架构，每层各司其职

```
口播稿 ──┐
         ├─① make_spec.py ─→ overlay-spec.json（时间轴+位置+动画意图，引擎无关）
视频/音频┘                          │
                                    ├─② research-protocol.md ─→ 联网找能跑的实现
                                    │                            └→ research-notes.md
                                    │
                                    └─③ engine-remotion.md / engine-hyperframes.md
                                        ─→ 渲染 ─→ final.mp4
```

| 层 | 谁负责 | 产物 | 要求 |
|---|---|---|---|
| **骨架层** | 本地脚本 `make_spec.py`（纯标准库，秒出） | `overlay-spec.json` | **必须离线可跑** |
| **肌肉层** | 本地 AI 联网检索 | `research-notes.md` + 代码片段 | **必须在线** |
| **落地层** | Remotion / HyperFrames / ffmpeg | `final.mp4` | **必须多选一** |

**为什么这么分？**

- 骨架层离线可跑 —— 没网也能出分镜，这是保底；
- 肌肉层必须在线 —— 保证不落后社区；
- 落地层必须多选一 —— 你机器上有什么就用什么，**不强推**。

`overlay-spec.json` 是**引擎无关的时间轴契约**，每个 segment 里有 `start / end / text / keywords / animation.type / slot / layer`。

**它的价值是：以后你换渲染引擎，分镜一份都不用重做。**

## 三、开工前 4 个开关

跟其他 Skill 一样，**一次问完，不来回追**：

| 开关 | 选项 | 默认推荐 |
|---|---|---|
| **画幅** | 竖屏 9:16 / 横屏 16:9 | 按源视频自动探测 |
| **动效密度** | 克制（每 8s 一张，同屏 1 张）/ 标准（每 5s 一张）/ 高密度（每 2.5s 一张，同屏 2 张） | ⭐ 标准 |
| **渲染引擎** | Remotion / HyperFrames / 自动选 | ⭐ 自动（装了哪个用哪个） |
| **要不要前景遮挡**（卡片压在人身前） | 要 / 不要 | ⭐ 不要 |

**「不要前景遮挡」这个默认，是因为做前景遮挡需要人像抠图。** 抠图质量差一点，真人出镜的片子就毁了。**默认所有卡片放在人后面或画面空白处。**

## 四、跑起来是这样

**第 1 步：出骨架（离线，秒出）**

```bash
python3 scripts/make_spec.py \
  --script 口播稿.md \
  --video  口播.mp4 \
  --srt    字幕.srt \
  --density standard \
  --out    task/<时间戳>_motion/overlay-spec.json
```

**没有视频文件、也没字幕时，至少把总时长钉准，别让字数硬估：**

```bash
python3 scripts/make_spec.py --script script.md --duration 85
```

跑完它会念一份摘要给你听：

```
== 口播动效骨架 ==
源视频：未提供｜85.0s（时长来源：given）｜9:16
时间戳：估算（4 字/秒）｜动画卡：8 张｜覆盖 26.1%｜单屏最多 1 张｜弃卡 0 条
分布：bottom 1｜left 1｜right 3｜top 3
类型：分屏对比(split-compare) 3｜清单逐条(checklist) 2｜品牌/产品名卡(logo-card) 2｜数字滚动卡(number-roll) 1
⚠️ 时间戳为估算（4 字/秒），交付前必须试听对齐
```

**这一步一定要让用户确认再往下走。** 分镜错了，后面全白做。

**第 2 步：联网补肌肉（核心一步）**

按检索协议执行，有硬预算：**≤8 次搜索、≤4 次全文抓取**，超预算直接降级。

命中的候选按**四维评分卡**筛——**能跑 / 许可 / 引擎匹配 / 迁移成本**——**至少留 3 个可复制的实现**（7 分以上才入库）。

每个候选都要在 `research-notes.md` 里记清楚：来源 URL、许可、许可证边界、最小可跑片段、迁移到本项目要改哪几行。

> **搜不到就如实降级**：走内置的纯 CSS/GSAP 最小实现，**绝不假装搜到了。**

这一步的产物允许为空（离线场景），但**必须显式写明「本次未联网，使用内置最小实现」**。

**第 3 步：落位校验（防遮挡）**

这一步专治「卡片糊脸」：

- **人脸安全区**内不得放任何卡（竖屏 `x 0.30–0.70`、`y 0.18–0.76`）
- 同一时刻同屏卡片数受密度上限约束，**超上限的那条直接弃卡**，并在 spec 里写明 `dropped` 原因
- 相邻两卡切换至少留 **0.2 秒空档**

> **有冲突就挪位置，不要缩卡片尺寸硬塞。** 卡片小到看不清，等于没加。

**第 4 步：渲染 + 三闸自检**

渲染完必须跑三道闸：

| 闸 | 标准 | 不通过怎么办 |
|---|---|---|
| **覆盖闸** | 动效总时长 / 视频总时长 **≥ 40%** | 太薄了，回 Step 3 补卡 |
| **遮挡闸** | 均匀抽 6 帧，确认无卡片压脸、无超出安全边距 | 挪位置 |
| **节奏闸** | 任意连续 5 秒内至少 1 个可见变化 | 太闷，加错峰或动效 |

抽帧命令：

```bash
ffmpeg -ss <t> -i final.mp4 -frames:v 1 check.png
```

**看完即删**，验证图不留在任务目录里。

## 五、7 条硬规则，其中两条是保命的

| # | 规则 | 违反的后果 |
|---|---|---|
| **R1** | 估算时长必须标注 `estimated`，交付前必须让用户试听对齐 | 卡点和讲话错位，整片废 |
| **R2** | 卡上所有数字 / 名称 / 引语只能来自口播稿或用户资料 | **编造数据，发出去就是事故** |
| R3 | 不做人像抠图 / 前景遮挡（除非用户明确要求并接受降级） | 抠图质量差直接毁掉真人出镜 |
| **R4** | 检索失败必须显式写明「本次未联网 / 未命中」 | 许可与来源不可追溯 |
| **R5** | 引入外部代码前先确认许可，GPL / 不明许可的**不用** | 商单成片有法律风险 |
| R6 | 不调用任何付费接口 | 试错成本 |
| R7 | 验证用截图看完即删 | 目录脏 |

**R2 我要单独说一句：卡上的数字只能来自你的稿子。**

它可以在你的稿子里有「省了 40%」的时候，把「40%」做成一个会滚动的数字卡；**但它绝对不能自己算一个数字出来。** 一个 AI 自动剪辑工具给你编出来的百分比，比没有动效糟糕一万倍。

**R5 也是真事。** 社区里的动效模板不一定都能商用，**GPL 或者写着「不明许可」的，统统不用。**

## 六、它也有一条挺有意思的逻辑

分镜脚本的关键词命中是有规律的：

- 阿拉伯数字 + 单位 → 数字滚动卡
- 「不是 A 而是 B」 → 分屏对比
- 「第一 / 第二」 → 清单逐条

所以你会发现：**有时候它给出的卡比你预期的少。**

这不是出错。正则只吃**显式结构**——中文数字、隐含对比、抽象概念，它不认。这些留给 Step 3 由 AI 补。

> **卡少 ≠ 出错。** 骨架阶段覆盖率低是正常状态，不是交付状态。

而且有个反直觉的事：**给了真实时间戳之后，卡可能反而变少。** 因为分句粒度跟着字幕走，不再按稿件重新切句。

> **不要因为数字好看就退回估算模式。** 时间准确性 > 卡片数量，缺的卡后面补。

## 七、它明确不做什么

v1 的坦白，我原样列出来：

1. **不自带动效库** —— 这是设计选择，不是没做完
2. **不做剪辑** —— 去口水词、重配音、改时长都不在范围，时间轴严格按输入走
3. **不做前景遮挡** —— 需要抠图，默认卡片一律在人后面
4. **图表数据不核实** —— 只搬运稿里的数字，不联网查证也不算账
5. **中文优先** —— 英文稿能跑，但切分质量下降
6. **渲染质量取决于本机环境** —— 没 Node 只能走 ffmpeg 兜底，动效会朴素一档

## 八、和其他 Skill 串起来用

```
knowledge-short-video（写口播稿）
        ↓  稿子 + segments.txt
[mograph] ← 真人出镜的动效包装
        ↓  overlay-spec.json
cover-hero ← 封面和视觉风格复用同一套设计令牌
```

**它能直接吃 knowledge-short-video 产出的 `script.md` 和 `segments.txt`。**

但要注意区分：**整条片都要生成、没有人出镜** → 用 knowledge-short-video；**真人出镜，要给口播包装** → 用这个。
