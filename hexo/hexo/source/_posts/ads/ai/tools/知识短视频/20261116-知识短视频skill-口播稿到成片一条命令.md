> **一句话总结**：写稿、配音、做动画、渲染、导出发布包——这一整套以前要折腾两天的活，现在是一条命令。而且它**强制输出动画视频**，不是把图片拼一拼。

大家好，我是程序员晚枫。

短视频这事，我算是踩得比较狠的。

做一条 60 秒的知识类短视频，你要处理的东西有：写稿、拆段、配音、做动画、渲染、导出、配封面、写文案。**七件事，任何一件没对齐，最后那条片子就是废的。**

我做过最痛的一次：稿子写好了，配音也合成好了，动画渲染完一看——**前三秒是黑的。**

原因很蠢：动画的第一帧用了「从透明渐入」，而渲染工具从第一帧就开始录，于是开头就是一片黑，配音已经在说话了。**画面和声音对不上，整个片子废了，重做。**

那次之后我明白了一件事：**做视频最贵的不是生成，是返工。**

所以我把这套流程整个写成了一个 Skill：**knowledge-short-video（知识短视频）**。

**SkillHub 发布页**：[知识短视频：https://skillhub.cn/skills/user_bf8c5b73/wanfeng-knowledge-short-video](https://skillhub.cn/skills/user_bf8c5b73/wanfeng-knowledge-short-video)

## 一、它适合做哪类视频

先划清楚范围，这很重要：

| 适合 | 不适合 |
|---|---|
| 60–90 秒 | 长讲解视频 |
| 9:16 竖版 | 横版 |
| 单人口播讲解型 | 真人出镜 |
| 无人出镜、以排版为主 | 纯图片拼接（**它强制输出动画视频**） |
| 中文 TTS 配音 | — |

**主题不限**：AI 工具、美食、职场、育儿、历史、健身、财经、心理……只要是「C 端知识科普」，都行。

## 二、先说三个工程决定，比功能更重要

功能谁都能写，**这三个决定才是这套流程能复用的原因**。

### 决定一：模板和口播稿解耦

> **一个任务 = 一份视觉模板 + 一份口播稿 → 多个配音变体**

意思就是：**稿子和视觉模板分开存。** 要换 TTS 引擎、换声音、换语速，走「变体」流程，**模板一个字都不用改**。

我一条稿子经常要出 2–3 版：标准版、快节奏版、换个声音版。以前每一版都要重做一遍动画，现在只需要跑一条命令。

### 决定二：时间由实测配音时长驱动

**不是拍脑袋估算。**

流程是：先把稿子合成配音 → **量出每一段实际有多长** → 把这些真实时间反向注入到动画模板里 → 渲染。

所以画面是跟着声音走的，**卡点是准的**。

### 决定三：一条命令产出变体

```bash
./tools/run-variant.sh <任务> <变体>
```

这一条命令串起了：**TTS → 拼接 → 注入时间 → QA → 渲染 → 抽帧**。

**任一步失败即停，并保留中间物。** 这一点很重要——半路失败时你能看到它停在哪一步、当时的中间文件是什么，而不是对着一个空白报错发呆。

## 三、开工前只问你 4 个问题

它有个 Step 0，**一次性把 4 个开关问完**，问完就干活，不来回追问：

| # | 开关 | 默认值 | 你要改成别的时 |
|---|---|---|---|
| ① | 封面风格 | **A · swiss-grid** | 4 选 1：swiss-grid / warm-grain / nyt-graph / embedded-captions |
| ② | 放不放 IP 信息（头像、slogan） | **不放** | 放的话你自己提供 IP 名和 slogan |
| ③ | 结尾要不要引导关注 | **不引导** | 要的话你给话术 |
| ④ | 用什么配音 | **系统默认 TTS** | 你也可以给 4 参数 / API 文档链接 / 客户端代码路径 |

**你沉默就全走默认，但必须问过。**

那两个默认「不放」是有道理的：**商业感越弱，平台越推荐。** 我自己号的封面到现在都没放 Logo。

## 四、7 步流程

```
Step 0  4 开关一次性确认
Step 1  写口播稿（≥20 句）+ 拆段 + 你确认
Step 2  落地视觉规范
Step 3  生成 3:4 封面
Step 4  写动画 composition（GSAP fromTo）
Step 5  TTS 合成配音 + 生成时间轴
Step 6  注入时间 + 渲染成片
Step 7  拼发布包（视频 + 封面 + 文案）
```

**顺序不可乱。** 特别是 Step 1 和 Step 5——**文本没确认就合成配音，等于 100% 返工。**

### Step 1 写稿：≥20 句是硬下限

少于 20 句就意味着内容没展开。视频的节奏也需要句子撑着，20 句是最低配。

另外两条要求：

- **第一句话必须把人留住。** 前 3 秒留不住人，后面写得再好也没用——**他已经划走了**。
- **要绑具体的东西。** 「AI 工具很好用」❌ → 「Cursor 进了我日常写作流，每周省 10 小时」✅。做美食就写「做了 20 次才稳定」；做职场就写「5 年 HR 看过的 1000 份简历」。

稿子还要拆成 `segments.txt`（段号|类型|文本），一段一行，**这个段数和动画模板里的占位符数量必须严格一致**。

### Step 4：必须是动画，不是图片拼接

这是它和一堆「一键生成视频」工具最不一样的地方。

它用 **GSAP 的 `fromTo`** 驱动元素动效——文字飞进来、卡片弹开、数字滚动。

**明确规定：不允许用 ffmpeg 把静态图 concat 起来。** 图片拼接出来的东西，平台一眼就能看出来是糊弄的。

## 五、5 条硬错误，工具会直接拦住你

这 5 条不是警告，是**lint / resync / render 工具会自动检测并中止**的硬错误：

| # | 硬错误 | 为什么致命 |
|---|---|---|
| **H1** | 段数与模板占位符对不上 | 对不上直接拒绝渲染 |
| **H2** | 残留 `__XXX__` 占位符 | 画面上出现 `__S03__` 这种鬼东西 |
| **H3** | 配音片段时间重叠 | **全黑视频的根因**（就是我踩过的那次） |
| **H4** | 动画元素缺 `data-track-index` | 时间轴对不上 |
| **H5** | 背景音乐音量 > 0.25 | 旁白被 BGM 盖住 |

**任何一条为真 → 修完再继续，不会产出一个残缺的视频。**

这 5 条全是从真实踩坑里长出来的。H3 就是开头黑屏那次的病根。

## 六、还有一条「最容易踩」的约定

> **所有音频文件必须在同一个目录。**

`scene_NN.wav`（每段单独配音）、`narration.wav`（拼接后的完整配音）、`timeline.json`（实测时长）——**三者必须在同一个目录里**。

TTS 写进去、拼接读同一个目录、注入时间也读它。

**把它们拆到不同目录，是历史返工的根因。** 我见过太多「文件明明在，为什么读不到」的怪事，根因都是这个。

## 七、目录长什么样

```
20260629_203000_什么是Token/
├── task-config.json          ← Step 0 的 4 个开关
├── 01-Script/
│   ├── script.md             ← 完整口播稿
│   ├── segments.txt          ← 拆好的段（≥20 段）
│   └── reverse-check.md      ← 段↔句 映射
├── 02-VisualSpec/
│   └── visual-spec.md        ← 视觉规范
├── 03-Cover/
│   └── cover.png
├── 04-Composition/
│   └── composition.html      ← GSAP 动画模板
├── 05-Audio/
│   ├── segments/             ← 每段独立 wav（中间产物，验证后删）
│   ├── narration.wav         ← 完整配音
│   └── timeline.json         ← 实测时长 + 映射
├── 06-Render/
│   └── video_full.mp4        ← 成片
└── 07-Publish/
    ├── video_full.mp4
    ├── cover.png
    └── publish.md            ← 标题 + 简介 + hashtag
```

**任务目录必须带时间戳**：`YYYYMMDD_HHMMSS_<任务名>`。为什么？**因为你一定会连续做多个任务。** 用 `Process/` 这种名字，第二个任务就把第一个覆盖了。

### 每做完一步，立刻清理中间产物

| 阶段 | 删掉什么 |
|---|---|
| Step 1 | 早期草稿（`script-v0.md`、`script-v1.md`） |
| Step 3 | 验证用的 `cover-v1.png` |
| Step 4 | 预览截图 |
| Step 5 | 每段独立 wav（留 `narration.wav` 就够） |
| Step 6 | 几千张原始帧 |

**保留：成品 + 配置。删除：截图、预览图、测试 HTML、中间 wav、原始帧。**

一个任务做完，目录里躺着几千张 PNG，下次你都不知道哪个是能用的。

## 八、交付给你的是 3 个文件

```
video_full.mp4 + cover.png + publish.md
```

**就这 3 个。** 不是全套。

短视频的最小发布包就是「视频 + 一张封面 + 一份文案」，你打开就能发。多给一堆中间文件，你反而不知道哪个该发。

`publish.md` 里是标题、简介和 hashtag。
