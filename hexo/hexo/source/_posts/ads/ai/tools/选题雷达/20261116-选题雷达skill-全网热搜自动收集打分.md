> **一句话总结**：每天早上打开 7 个平台翻热搜，眼睛和时间全耗在「看」上——这个 Skill 替你拉完、过滤完、打分完，直接给你一张「今天值得跟」的清单。

大家好，我是程序员晚枫。

我写公众号、做视频，最大的时间黑洞不是写稿，是**找选题**。

你知道的，一个上午刷 7 个 App：微博热搜、抖音热点、知乎热榜、小红书热门、B 站排行、头条热榜、百度热搜。刷完一圈，眼睛累、脖子酸，最要命的是——**刷到的东西七成跟你没关系**。剩下三成里，还有两成是昨天、前天、大前天已经火过的。

于是我写了个小工具，把它变成了一个 Skill：**选题雷达（hot-topic-radar）**。

它只干一件事，也只干这一件事——**告诉你今天发生了什么、哪个值得跟**。剩下的它一个字都不多写。

**SkillHub 发布页**：[选题雷达：https://skillhub.cn/skills/user_bf8c5b73/wanfeng-hot-topic-radar](https://skillhub.cn/skills/user_bf8c5b73/wanfeng-hot-topic-radar)

## 一、它到底做了什么

整个流程五步，掐掉头尾，中间全自动化：

```
拉数据（多平台热搜，按平台分别抓）
  → 关键词过滤 + 领域相关度打分
  → 记忆去重（同一热点 7 天内不重复推）
  → 按「热度 × 相关度」排序
  → 输出 TOP 10 候选清单（带原文链接）
```

跑完你会拿到一个文件，路径是 `workflow/每日热点/YYYY-MM-DD-hot-topics.md`，长这样：

```markdown
## 1. OpenAI 推出 GPT-6，多模态能力大幅提升
- **平台**：微博
- **发布时间**：00:15
- **热度值**：92 / 100
- **相关度**：0.75（命中：AI、ChatGPT）
- **综合分**：87.3
- **链接**：https://weibo.com/...
```

**每条都带平台、热度、命中了哪个关键词、原文链接。**你不用再去搜「这条是哪年的新闻」，也不用回忆「我是不是写过这个」。

## 二、关键在两个地方

### 第一个：不是按热度排序，是按「热度 × 相关度」

这是它和那些「今日热榜搬运」最大的区别。

热搜第 1 位，热度值算满分。问题是：**第 1 位可能是个明星塌房**，跟你半点关系没有。

所以它的公式是：

```
综合分 = 热度 × 0.6 + 相关度 × 0.4
```

相关度怎么算？很土但很有效——**标题里每命中一个你的关键词，加 0.25 分，封顶 1.0**。同时还有一个「排除词」名单，命中就直接归零：

```yaml
keywords:
  - AI
  - 大模型
  - ChatGPT
  - Claude
  - 编程
  - 副业

exclude_keywords:
  - 娱乐
  - 明星
  - 电视剧
```

这两个权重和名单都在 `radar-config.yaml` 里，想调随时改。

**说白了，热搜是被动看的，关键词是把「我关心什么」写给机器看。** 你换了赛道，改两行配置就行，不用换工具。

### 第二个：7 天内不重复推

这是我最常用的一个功能。

它维护一个 `memory/dedup-history.jsonl` 文件，每推过一条就记一行：标题、平台、推送时间、链接。

下次跑的时候，先读历史，再拿今天的新热搜做模糊匹配——**相似度 ≥ 85 分就算同一条**（标题 15% 以内的改动都算同一件事，所以「XX 公司发布 GPT-6」和「XX 公司正式发布 GPT-6」不会推两遍）。

7 天窗口内的直接跳过。每 30 天自动清一次旧记录，文件不会越滚越大。

**为什么是 7 天？** 因为自媒体的热点生命周期差不多就是一周。一周前火过的话题，今天再写就是炒冷饭。

## 三、说实话：现在通了三个平台

这点我必须写清楚，不然就是吹。

抓取脚本 `fetch_hot.py` 的框架是全的——配置加载、多平台分发、归一化、打分、去重、排序输出，六道工序都跑通了。但**每个平台的抓取函数是分开实现的，各家反爬强度差得很远**：

| 平台 | 状态 | 原因 |
|---|---|---|
| 微博热搜 | ✅ 能抓 | 公开接口 |
| 今日头条 | ✅ 能抓 | 公开接口 |
| 百度热搜 | ✅ 能抓 | 公开接口 |
| 抖音热点榜 | ⏳ 待补 | `_signature` 反爬，建议走第三方聚合站 |
| 知乎热榜 | ⏳ 待补 | 当前接口需要登录态 |
| 小红书热门 | ⏳ 待补 | 风控严 |
| B 站热门 | ⏳ 待补 | 触发风控，需要带 cookie |

**为什么不全接上？** 因为接平台这件事本质是「追接口」，追得完今天追不完明天，还天天有人改页面。我宁愿先把**打分、去重、排序这三件真正值钱的事**做扎实，剩下的按实际需求一个个补。

而且补的时候是有规律的——这几个平台的坑我都写在 SKILL.md 里了：必须带真实浏览器 UA、加 `Accept-Language`、补 `Referer`、处理 gzip 响应、403 和 SSL 超时必须走重试而不是直接报错。照着抄就行。

## 四、怎么用

**第一步：改配置。** 复制一份 `radar-config.example.yaml` 成 `radar-config.yaml`，把关键词换成你的领域：

```yaml
timezone: Asia/Shanghai
lookback_hours: 24                # 拉最近 24 小时的
top_n: 10                         # 输出 TOP 10

keywords: [AI, 大模型, ChatGPT, Claude, 编程, 副业]
exclude_keywords: [娱乐, 明星, 电视剧]

platforms:
  - weibo
  - toutiao
  - baidu

weights:
  hotness: 0.6
  relevance: 0.4

dedup:
  enabled: true
  window_days: 7
```

**第二步：跑。**

```bash
# 跑今天的
python scripts/fetch_hot.py

# 只打印不写文件（先看看质量）
python scripts/fetch_hot.py --stdout

# 强制重推（清掉去重记忆）
python scripts/fetch_hot.py --clear-memory
```

**第三步：看清单。** 打开 `workflow/每日热点/` 下当天的文件，挑一条你真有话说的。

**就到这里为止。** 它不会替你写稿，也不会替你想标题——**这是故意的**。

## 五、它明确不做什么

这一点我写得很死，因为它决定了这个工具好不好用。

| 不做 | 为什么 |
|---|---|
| 不写文章、不写脚本、不写视频 | 那是下游的活，不该它管 |
| 不主动发布任何内容 | 雷达只收集情报，发不发你说了算 |
| 不替你决定写什么 | 清单是候选，不是命令 |
| 不爬需要登录才能看的页面 | 登录态一律不碰 |
| 不编数据 | 来源不明的标「待核实」 |

> **设计哲学：选题是独立任务，不预设下游消费者。**

这条是我写这个 Skill 时最坚持的一点。以前我的选题流程是「选题 → 写稿 → 配音 → 排版」一气呵成，结果每次卡在写稿那儿，前面拉的热点全白费。

**拆开之后，选题可以每天单独跑、单独看、单独攒。** 攒到周末翻一翻，一周的选题池子就有了。

## 六、和另一个选题 Skill 的关系

我还有一个专门盯 AI 圈的选题工具（`aihot-topic-selector`，专攻 AIHOT 的数据源，每天按「核心 2 问」筛 1 条出来），下一篇单独写。

两个不冲突，是**互补**：

| | 选题雷达（hot-topic-radar） | AI 热点选题（aihot-topic-selector） |
|---|---|---|
| 范围 | 全网，跨平台 | 只盯 AI 圈 |
| 输出 | TOP 10 候选清单 | 每天选 1 条 + 建任务目录 |
| 适合 | 泛领域账号、要广度 | 垂直 AI 号、要深度 |

**并行跑就行。** 一个给你广度，一个给你准。

## 七、怎么装

**方式一：从 GitHub 拉源码（本地用）**

```bash
git clone https://github.com/CoderWanFeng/wanfeng-skills.git
cd wanfeng-skills/skills/hot-topic-radar
```

需要装两个包：`pyyaml`（读配置）和 `rapidfuzz`（模糊去重）。脚本是纯 Python 标准库打底，不装浏览器、不装重东西。
