*WorkBuddy 开发者沙龙·重庆第二场 活动总结*

大家好，我是程序员晚枫。

11 月 14 日下午，重庆第二场 WorkBuddy 开发者沙龙办完了。

四位讲师，四个完全不同的场景：一个人扛六个项目的职业院校老师，一个被琐事填满的小程序管理员，一个算不清库存的服装电商，一份改出十个版本的合同。主持人昭意把整个下午串了起来，我作为出品人做了开场致辞。

散场后我把现场相册 219 张照片从头翻到尾，把每一页能看清的课件都读了一遍。读完发现，四个人讲的其实是同一件事：

**别把 AI 当问答机。把活交代清楚，它才会替你干。**

这句话，正好就是第一位讲师的标题：别「问」AI，去「派活」。

## 三、四位讲师，讲的都是怎么给 AI 派活

### 叶鹂君：底气是一次交付验证出来的

叶鹂君来自重庆工信职业学院轨道交通信号专业，官方头衔是正高级工程师。

![叶鹂君的标题页](https://raw.githubusercontent.com/CoderWanFeng/img-cdn/master/20261114-workbuddy-cq2-recap-09-ye-lijun.jpg)

*14:12，叶鹂君开讲。*

他的开场页叫「一个普通的晚上，六件事压在同一周」：

- 六个方向的项目台账，明天要交阶段汇总，还空着两行；
- 一门从零开始的新课，大纲刚定，讲义、课件、作业都还没影；
- 一篇返修的论文，意见没回完，旁边那套仿真实训系统也没调利索。

底下一行字：**以前这些活，是一个科室分着干的。现在只有我一个人，外加一台电脑。**

凭什么敢接？下一页给了答案：几个月前，他用 QCLAW 把一整件事从头到尾跑完，自己在旁边只做判断。那次之后他确认了一件事：它能替他交付结果，不只是陪他聊天。

页底一句话我很喜欢：「换赛道不可怕，可怕的是没验证过自己能不能把活干出来。」

我的理解是：**派活之前，先用一件完整的小事验证 AI 能交付。** 验证过一次，才敢把第二件、第六件交出去。

### 杨权：连接器管「连上」，技能管「怎么做」

杨权负责的「诗社 Event」，是一个面向校友会、商会等组织的小程序，承载日常管理与运营。

他的出发点很朴素：**管理员的日常，不该被琐事填满。** 发布活动、管理帖子、记账、发公众号文章，这几件事能不能交给 AI？

![杨权的目录页](https://raw.githubusercontent.com/CoderWanFeng/img-cdn/master/20261114-workbuddy-cq2-recap-10-yang-quan.jpg)

*14:39，杨权的目录：需求、连接器和技能、REST API、SKILL + MCP Server、三个真实演示。*

全场我觉得最值得普通人记住的一页，是他抛出的疑问：腾讯文档、QQ 邮箱，为什么又有「连接器」，又有「技能」？

课件上的答案：

- **连接器管「连上」**：鉴权、暴露工具、传输数据；
- **技能管「怎么做」**：流程、步骤、操作手册（SOP）。

翻成大白话（这是我的比喻）：连接器是给 AI 一张门禁卡，技能是给它一本岗位手册。只有门禁卡，它进得去但不知道干什么；只有手册，它会干却进不了门。杨权给的方案，就是 SKILL 加 MCP Server 两样一起上。

### 吴国鑫：库存算不清，是五张表没对上

吴国鑫有 20 年 C++ 开发经验，这场的题目却是「不写代码」。

他先把问题摆出来：服装电商款多、SKU 多、季节性强，数据散在好几张表里。传统做法是导出多张表、VLOOKUP 拼表、做数据透视、人工判断过季和死货，最后汇总成报表。

毛病有四个：耗时长；公式易错，错一格整张表都偏；口径靠个人经验，过季怎么算没标准；换人就断档，只有一个人会做。课件上的总结是：「每一步都对，但每一步都靠人。」

他给的解法是一道加法：**多张表 + 一份对应关系说明 + 一句话目标 = AI 自己干活。** 那份对应关系说明，他叫它「给 AI 的交接文档」。

![吴国鑫讲三种模式](https://raw.githubusercontent.com/CoderWanFeng/img-cdn/master/20261114-workbuddy-cq2-recap-11-wu-guoxin.jpg)

*15:26，「三种模式，就是三种带实习生的方式」。*

这一页把三种模式比作带实习生：

- 智能体：会自己动手的实习生，目标和做法都清楚时用；
- 计划：先交方案再动手，任务复杂、材料多、怕它跑偏时用；
- 问答：只请教不动手，你自己还没想清楚要做什么时用。

页底一句：「模式不是等级，是场合。」

### 张展瑞：缺的不是副本，是一条能恢复的历史

张展瑞（旧亭离风）的副标题是「Git 不只是程序员的工具，用 Git + WorkBuddy 重塑文字工作流」。

他放出一个文件夹：项目开发合同 V1.0_副本、V1.1_法务留痕版、V1.1_张总改、V1.5_最终版、V1.5_最最最终版、V2.0 最终版_副本 (2)……一共十份。

![张展瑞讲「你有几个最终版」](https://raw.githubusercontent.com/CoderWanFeng/img-cdn/master/20261114-workbuddy-cq2-recap-12-zhang-zhanrui.jpg)

*15:49，「你有几个『最终版』？」*

紧接着三个问题：哪个才是最新的？两份之间到底改了什么？删掉的话还能找回吗？

他的判断是，复制副本能留底，但它把版本管理变成了文件名管理。**我们缺的不是更多副本，而是一条能比较、能恢复的历史。**

可 Git 对普通人门槛太高。他的办法是不背命令，直接跟 WorkBuddy 说：「把当前文件夹变成 Git 仓库」「看看这次改了什么，先别提交」「帮我提交 git 吧，说明写清楚，然后推送到 github」。课件上的原话是：WorkBuddy 接手技术操作，你说清目标、核对结果。

### 四个人的共同点

叶鹂君说「派活」，杨权给 AI 配门禁卡和手册，吴国鑫写交接文档，张展瑞让你「说清目标、核对结果」。

**没有一个人在讲哪个模型多聪明，四个人都在讲同一件事：活要怎么交代。**

## 四、台下拿起话筒的人，比我预想的多

每场分享后面都留了提问。我按照片数了一下，四段问答里至少有 15 人次在台下站起来、拿起话筒。

有个细节：叶鹂君讲完坐回台下，到吴国鑫那场问答时，他自己又拿起话筒提问。讲师之间互相追问，是我最想看到的场面。

16:27 开放麦开始，出品人先上——我上去把 WorkBuddy 的任务列表投上屏，开了个头。<!-- 待作者确认：16:27–16:34 照片里投屏的 WorkBuddy 任务列表（含「分析库存数据并分类库存」「AI技术沙龙活动回顾文章撰写」等条目）是否为本人电脑；若不是，删去「把 WorkBuddy 的任务列表投上屏」 --> 之后两位参会者轮流上台投屏：一位打开了 WorkBuddy 的技能页面，另一位演示了一套给医院委员会开会投票用的系统，会议列表里能看到「投票中」「已截止」，还有一个「大屏」按钮。

后面这位，16:18 张展瑞那场问答时还在台下站着提问，半小时后就站上了讲台。

**从提问的人变成演示的人，中间只隔了半小时。** 我觉得这是整个下午最值钱的半小时。

## 五、合影那 3 张，是全场被看得最多的照片

219 张照片里浏览量最高的 3 张，全是 17:01 那张合影：64、54、48 次，全部照片的中位数只有 12 次。

![重庆站第二场大合影](https://raw.githubusercontent.com/CoderWanFeng/img-cdn/master/20261114-workbuddy-cq2-recap-07-group-photo.jpg)

*17:01，大合影。*

合影上线最晚，却被看得最多。**合影不是流程的最后一步，是参与者真正带走的那一张。**

## 六、这场该改的一环：三分之一的照片晚了两小时

现场上线的 146 张，从按下快门到出现在相册里，中位数 15.3 分钟；另外 73 张（33.3%）是 19:35 以后一次性补传的，平均只被看了 5.7 次，现场那批是 15.1 次。

人散了、群安静了，照片就只剩存档价值。下一场要改的事很具体：**照片在散场前传完。**

---

四个行业，四个场景，一句结论：**AI 不缺能力，缺的是一份交代清楚的活。**

对我这个出品人，这场也留了三件作业：合影早点认真拍，照片散场前传完，话筒多往台下递。

六个项目、小程序琐事、五张库存表、十份合同——这四个场景里，哪个最像你现在每天在干的活？评论区聊聊。

**科技不高冷，AI 很好用。**

我是程序员晚枫，关注我，带你一起玩 AI。
